# 小众优选 · 国内电商站 MVP

零依赖（仅用 Node.js 内置 `http` / `crypto` / `fs`）的国内电商站原型：商品浏览 → 购物车 → 下单 → **微信支付 V3 / 支付宝** 接入 → 异步回调 → 订单状态流转 → **退款 + 对账**。界面参考 newbee-mall、litemall 等开源商城的成熟范式（首页门户/轮播、分类导航、新品推荐、商品详情、订单时间线、对账中心等）做了现代化打磨。

> 默认 `PAYMENT_MODE=mock` 即可**无商户号跑通全链路**；填好商户密钥后切到真实支付，签名/验签/解密逻辑已通过自测。

## 界面与功能模块

| 页面 | 路径 | 说明 |
| - | - | - |
| 首页门户 | `/` | Hero 自动轮播 + 全部分类图标导航 + 新品上线 + 人气推荐楼层 + 服务保障条 |
| 商品详情 | `/products/:id` | 图集切换、数量步进、立即购买/加入购物车、价格与销量、状态时间线 |
| 分类页 | `/category?cat=` | 按分类筛选商品 |
| 搜索 | `/search?q=` | 标题/描述/分类模糊搜索 |
| 购物车 | `/cart` | 数量步进、删除、实时合计 |
| 结算 | `/checkout` | 收货信息 + 订单汇总 |
| 支付 | `/pay/:id` | 微信/支付宝/模拟 渠道卡片选择（Native 扫码 / H5 / 跳转） |
| 订单详情 | `/orders/:id` | 状态时间线、退款申请与进度 |
| 对账中心 | `/reconcile` | 按日期比对本地订单与各渠道账单，输出差异 |
| 管理后台 | `/admin` | 全部订单表格化查看 |

## 1. 快速开始（本地，无需任何商户号）

```bash
cd domestic-shop
cp .env.example .env        # 默认 PAYMENT_MODE=mock
node src/server.js          # 或 npm start
```

打开 <http://localhost:3000> ：

1. 首页选品「加入购物车」→ 购物车 → 去结算
2. 填收货信息 → 提交订单 → 进入支付页
3. 选「模拟支付」→ 点「我已支付」→ 订单状态变为 `paid`
4. 订单详情页可「申请退款」；管理后台 <http://localhost:3000/admin> 查看全部订单
5. 对账中心 <http://localhost:3000/reconcile> 选择日期执行对账，比对本地订单与各渠道账单

数据落盘在 `data/products.json`、`data/orders.json`（生产请换数据库）。

## 2. 切换到真实支付

编辑 `.env`，把 `PAYMENT_MODE` 改为 `wechat` / `alipay` / `all`，并填入对应密钥：

### 微信支付 V3

- `WECHAT_MCH_ID` 商户号、`WECHAT_APP_ID` 公众号/小程序 AppID
- `WECHAT_MCH_PRIVATE_KEY`（PKCS#8 私钥 PEM，或 `WECHAT_MCH_PRIVATE_KEY_FILE` 指向文件）
- `WECHAT_API_V3_KEY`（32 字节 APIv3 密钥，用于回调解密）
- `WECHAT_SERIAL_NO` 证书序列号、`WECHAT_PLATFORM_PUBLIC_KEY` 平台公钥（用于回调验签）
- PC 网站走 **Native 扫码**；手机浏览器走 **H5 唤起微信**（按 UA 自动切换）

### 支付宝

- `ALIPAY_APP_ID`、`ALIPAY_PRIVATE_KEY`（应用私钥 PKCS#8）
- `ALIPAY_PUBLIC_KEY`（支付宝公钥，用于回调验签）
- 电脑网站支付 `alipay.trade.page.pay`；手机网站支付 `alipay.trade.wap.pay`

> ⚠️ 真实回调 `notify_url` 必须是**公网可达 + HTTPS + 已完成 ICP 备案**的域名，本地 `localhost` 收不到微信/支付宝回调。开发期可用内网穿透（如 frp/ngrok）临时暴露，上线再换正式域名。

## 3. 支付费率（一般实物小商品类目，2026 参考）

| 渠道    | 网站适用产品            | 费率       | 到账                 |
| ----- | ----------------- | -------- | ------------------ |
| 微信支付  | Native 扫码 / H5 唤起 | **0.6%** | T+1                |
| 支付宝   | 电脑网站 / 手机网站支付     | **0.6%** | 余额实时（新签 90 日内 T+1） |
| 银联云闪付 | —                 | ~0.38%   | T+1                |
| 数字人民币 | 数币收款              | **0%**   | 实时                 |

- 特殊类目（游戏、网络广告、休闲娱乐等）费率 **1%**。
- **退款时服务费不退**。
- 小微/个体工商户有降费优惠活动，以商户平台显示为准。

## 4. 合规清单（上线前必办）

| 事项        | 说明                                   | 主管     |
| --------- | ------------------------------------ | ------ |
| 营业执照      | 无货源建议注册**个体户**（纯线上可用「网络经营场所」登记，自办免费） | 市场监管局  |
| ICP 备案    | 境内服务器必须备案（免费，7–20 工作日），备案号悬挂首页       | 工信部    |
| ICP 经营许可证 | 有偿卖货/会员/广告必须办（免费审批，约 1–3 月）          | 省通信管理局 |
| EDI 许可证   | **仅平台型**（邀商家入驻抽佣）需要；纯自营单品牌不需要        | 省通信管理局 |
| 公安联网备案    | 已 ICP 备案后做                           | 属地公安   |
| 类目资质      | 卖食品需《食品经营许可证》；医疗器械/药品另有许可            | 对应监管部门 |

> 税务：办照即申报；个体户可享小规模纳税人增值税减免；无票收入也要申报，留存订单/物流凭证 ≥5 年。  
> 2026/10/12 起**个人微信收款码不得用于经营**，必须接商户号。

## 5. 代码结构

```
domestic-shop/
├─ .env.example          # 配置样例（商户号/密钥/支付模式）
├─ src/
│  ├─ config.js          # 读取 .env
│  ├─ store.js           # JSON 文档存储
│  ├─ products.js        # 种子商品（蓝海小众日用品）
│  ├─ orders.js          # 订单 + 状态机(created→paid→shipped→completed→refunding→refunded)
│  ├─ crypto.js          # RSA 签名/验签 + 微信 AES-GCM 解密
│  ├─ payment/
│  │  ├─ wechat.js       # V3 Native/H5 下单、退款、回调/退款回调验签解密、对账单地址
│  │  ├─ alipay.js       # 电脑/手机网站支付、退款(同步)、回调验签、对账单地址
│  │  ├─ mock.js         # 本地模拟支付 + 退款
│  │  └─ index.js        # 统一支付适配层（按模式/设备选择渠道；refund 统一退款）
│  ├─ reconcile.js       # 对账引擎：本地订单 vs 各渠道账单，差异比对 + 每日定时调度
│  └─ server.js          # 零依赖 HTTP 服务：页面 + 下单/支付/退款/对账 API
├─ public/               # 前端静态资源（购物车用 localStorage）
└─ data/                 # 运行时数据（gitignore 建议）
```

### 关键设计

|   |   |   |
| - | - | - |

|   |   |   |
| - | - | - |

- **统一支付适配层** `payment/index.js`：业务层只调 `initiate(provider, opts)`，返回 `{method:'qr'|'redirect'|'mock', ...}`，换渠道/加渠道不动业务代码。
- **回调幂等**：`handlePaid` 对重复通知直接返回成功，订单状态不会重复流转。
- **微信 Native**：返回 `code_url` 由前端渲染二维码（建议引入 `qrcode` 库生成图片；当前回退为展示字符串）。
- **退款**：订单状态机新增 `refunding → refunded`（异步渠道如微信等回调确认；`refunding → paid` 为退款失败回滚）。`mock`/支付宝为同步，申请即标记 `refunded`；微信为异步，需 `/api/callback/refund/wechat` 确认。
- **对账**：`reconcile.js` 比对本地已支付订单与各渠道当日账单，识别**漏单 / 账外收款 / 金额差异**三类问题；mock 模式生成模拟账单（含 1 条幽灵记录演示差异检测），真实模式请求微信 `tradebill` / 支付宝 `bill.downloadurl.query` 并解析。每日 03:10 自动对账（仅真实支付模式启用）。

### 退款与对账 API

| 方法   | 路径                               | 说明                                                                   |
| ---- | -------------------------------- | -------------------------------------------------------------------- |
| POST | `/api/refund/:orderId`           | 申请退款，body `{amount?, reason?}`；返回 `refunded`（同步）或 `refunding`（异步待回调） |
| POST | `/api/callback/refund/wechat`    | 微信退款异步通知（验签+解密，SUCCESS 标记已退款）                                        |
| POST | `/api/callback/refund/alipay`    | 支付宝退款异步通知（验签，标记已退款）                                                  |
| GET  | `/api/reconcile?date=YYYY-MM-DD` | 手动触发对账，返回 `{summary, mismatches, bills}`                             |
